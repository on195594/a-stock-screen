## 架构与核心方案速览

- **定位**：单用户、Web端（兼容移动端浏览器）、Linux VPS、Flet 动态 Web。只做个人研究记录与同业资料变化发现；不做交易、账户、回测、模型或定时选股。
- **核心算法**：完全复用 `screen.py` 中的 `peer-screen-v1`，保持公式与排名逻辑不变。
- **存储合同**：VPS 上单个 SQLite 工作区，仅建 3 张业务表（个人记录、运行索引、更新任务）；原始快照事实仍保存在普通 JSON 文件。
- **并发与更新**：网页提交任务写入任务表，后台独立串行 Worker 执行更新，页面关闭不丢任务。
- **认证**：生产环境采用 GitHub OAuth 同标签页回跳 + 服务端数字 ID 白名单。

## 交付阶段路线图

| 阶段 | 交付目标 | 状态 | 关键产出 |
|---|---|---|---|
| **S1** | Web端可看资料、保存判断（兼容移动端）、重启不丢 | **当前进行** | 独立环境与锁文件、三表初始化 (`workspace.py`)、三张基础页面、OAuth 边界、4 个 make 命令 |
| **S2** | Web端提交更新任务、后台完成 | 待 S1 验收 | 任务状态持久化、独立 Worker 进程、失败恢复 |
| **S3** | 未阅事实变化审查、移动端收口 | 待 S2 验收 | 快照差量提示、真机适配、部署脚本 |

## 常用命令与入口

```bash
# 1. 算法与既有测试验证（当前环境直接可用）
uv run pytest test_screen.py -q

# 2. S1 交付后建立的统一工程入口
make setup        # 安装依赖与浏览器环境
make demo         # 幂等启动本地离线合成演示
make check        # 运行全套测试、代码风格与类型检查
make test-mobile  # 隔离运行移动端浏览器关键路径测试
```
