## S1：Web端能看资料、保存判断（兼容移动端），重启不丢

**交付：可登录的基础界面＋离线演示＋个人状态。先不联网抓财务、不实现worker。**

### 要改什么

1. **建立独立环境。** Python3.13；Flet1.0系列精确锁版，锁定匹配的Web包/CLI。生产最小依赖为Flet动态Web所需包、Uvicorn、既有TuShare依赖；开发组为pytest、必要禁网工具、Ruff、mypy及Playwright；Flet CLI/MCP放可选tools组，缺MCP不能阻止demo或check。不要装桌面/音视频/图表等无用扩展。生成并提交 `uv.lock`，不升级tracker环境。没有有效锁版前不复制旧API；先让最小ASGI导出、页面事件、移动语义定位跑通，随后在同一S1继续页面，不另起选型工程。检查sqlite3实际运行库及设计4.5的WAL条件；不满足时可显式初始化DELETE模式demo，不静默改生产。
2. **复跑原测试。** 保存原算法测试，不拿删测试换绿灯；测试覆盖变化时只修改确实被新UI范围取代的入口期待。保留CLI离线重放行为。
3. **初始化工作区和导入。** `workspace.py` 实现设计附录A；显式事务、模式标记、user_version/schema核对、相对路径与哈希校验。维护入口实现幂等init和显式import；网页/worker启动不自动建表。导入原字节复制进受控目录，相同内容只登记一次；排除重放副本作为新观察，未知规则/字段不足只供历史查看。production拒绝fixture来源。未知来源不能因JSON可解析就进入当前排名。
4. **做三张页面。** 首页、同业发现的“现有结果视图”、公司详情；两个底部导航。页面用完整fixture，不为等真实接口而留空。状态、理由、下一步、笔记链接使用SQLite；首次加入expected_revision=0，重复加入不覆盖备注，保存响应丢失可安全重读/重试。保存和最小已阅接口在S1实现，跨运行变化展示留S3；界面传include_personal_notes=True，不因服务默认隐私设置把自己的备注隐藏。
5. **接认证。** 按设计接GitHub OAuth＋数字ID白名单；优先同标签页授权，正确await官方回跳调用并验证state关联。关闭ASGI上传入口，配置Host及WebSocket Origin检查并透传lifespan；只做HTTP检查不算完成。demo同时限制绑定、Host/Origin和工作区模式，不信任转发头；生产不允许绕过。无OAuth配置时demo可用，生产启动必须拒绝。首版不保存OAuth Token到客户端或数据库，不做长期免登录。授权上下文可撤销；过期/退出取消页面轮询，旧异步结果返回不能重新展示私人数据。框架会话超时、OAuth state超时、业务8小时期限分别设置与测试，不能把重连当新登录。
6. **给Codex稳定命令。** 建立下面四个make目标，并在README说明真实运行方式。

| 项目命令 | 要实现的行为 |
|---|---|
| `make setup` | 已有锁文件时frozen安装；首次锁定由S1显式解析。准备动态Web公共资源；不读相邻环境或生产 |
| `make demo` | 幂等初始化demo并导入fixture后启动动态Web；仅loopback、禁转发头、不读Token。重复启动保留本人演示记录，不自动清库 |
| `make check` | 原测试＋当前新增单元/服务测试、Ruff check/format、mypy；不会请求真实接口 |
| `make test-mobile` | 启动隔离临时demo而非开发者的demo库；跑浏览器关键路径并保留失败截图。缺浏览器/断言失败返回非零，不伪装PASS |

锁文件尚未建立时，由S1先执行依赖解析并记录安装结果；此后setup/CI使用frozen模式，不每次安装“最新”。首次安装测试工具和浏览器资源与正式禁网测试分开；README给出一次性 `uv run --frozen python -m playwright install chromium` 等实际可用安装步骤。设置FLET_WEB_NO_CDN=true，确认所需引擎/字体可从本地服务取得；正式浏览器测试允许loopback HTTP/WebSocket，阻止外部提供方。不能把“禁网”实现成连demo自身都无法访问。

## S2：Web端提交更新，关闭页面后服务器继续完成

**交付：受控任务＋同业扫描＋关注事实更新。页面事件不抓数据。**

### 要改什么

1. `services.py` 实现请求与查询接口。先查request_id/别名与原intent，确认不是重试后才读取watch清单与已证明日历，冻结codes/target_date。别名合并和active去重在同一事务；关注清单改变后重发旧ID仍返回原任务，不错误地重新求范围。空清单拒绝，不生成假成功任务；paused默认不更新。
2. `worker.py` 实现单实例文件锁、队列领取、真实进度和终态；API在数据库事务外执行。不用Flet Page、内存队列、页面线程或未经用户点击的定时发起。进程锁持有到退出；缺Token或模式错误时先拒绝启动，不批量领取任务使它们失败。SIGTERM停止领取并有限结束，强制中断由启动恢复接管。
3. 在 `screen.py` 中仅提取必要的按证券读取函数，复用原范围/版本/排名代码。补充按数据核验推进的financial_checked_at；默认上一已证明交易日并冻结；captured_at在读取结束后记录。交易日期和公告日期比较用Asia/Shanghai，库内时间统一UTC，不能直接截取UTC日期替代中国市场日期。核对返回证券、重复行和源日期，临时失败不能标业务排除。不要顺手更改ROE/PB公式。
4. peer任务仍最多50家；watch任务只读取固定关注代码，不再要求它们入围原关注池或前50，不重新排名。单任务超过50家明确提示，不静默截取。watch对非正PB/ROE和已知ST也可读取事实；无法确认当前身份时标缺口，不自动删除或写新名次。
5. 对缺失/不合格/冲突/网络失败分别记录。保持普通JSON快照与三表设计；只有数据库登记成功才显示新run。partial诊断不替换完整榜，job succeeded也不等于全部数据成功；facts_usable与eligible分开。按设计的固定job_id文件先写、数据库后登记覆盖中断窗口；恢复时核对job、intent、日期、代码范围和哈希，不能仅因存在snapshot.json就补登记成功。
6. 页面提交后立即转任务页，显示真实阶段；任务列表从SQLite重建。关闭页面后worker继续，回来后能够找到原任务。页面断线重连不能再次自动提交更新。
7. 保持所有代码可在demo模式执行：demo worker使用固定fixture并模拟失败，不连接TuShare。业务网络请求边界可替换为测试函数，不为此造插件框架。

先启动独立临时demo，检查Flet可访问性语义树实际是否开启；需要时使用官方“Enable accessibility”入口开启。这一步允许针对框架启用按钮适配，业务断言仍用可访问名称。以按钮文本、label、tooltip、Semantics定位“加入观察/保存/变化已阅”，不用脆弱的固定屏幕坐标作核心断言。

首个测试必须实际点击保存并检查SQLite/重开页面后的内容，不能只验证根页面200、Flutter资源加载或截图存在。`flet test`原生设备测试不能冒充动态Web测试。用固定fixture和模拟worker，不接真实数据接口；浏览器只放行loopback HTTP/WebSocket，中文字体和引擎资源在安装阶段准备。测试退出清理自己创建的进程与临时库，不删除开发者demo。若缺浏览器或语义定位未跑通，make test-mobile非零退出并说明；不得把skip/截图存在计成PASS。

## 3. 部署资产要生成什么

以下是编写时拟定的 systemd/Caddy 部署资产，不是当前本机操作说明；当前已采用 Docker Compose + Nginx 运行 Web；本工作区有独立同业 worker 的 Compose 配置但未部署，备份/恢复入口未实现。实际部署及限制见[项目说明](../README.md)：

| 资产 | 关键内容 |
|---|---|
| `deploy/Caddyfile.example` | HTTPS域名、localhost反向代理；不配私有目录file_server；WebSocket与回调可用 |
| `deploy/a-stock-screen-web.service` | 低权限、固定提交/venv、web.env、单ASGI worker、Umask=0077、无reload；保护代码、只开放运行目录写权限 |
| `deploy/a-stock-screen-worker.service` | 同提交、worker.env、串行锁、SIGTERM处理、Restart=on-failure；不自动重试failed/interrupted |
| `.env.example` | 公开的回调域名示例与凭据占位符；不含真实 OAuth ID、secret 或 Token |
| README部署小节 | 角色配置、SQLite模式与库版本、init/import、启动、OAuth/WS检查、备份/新目录恢复、回滚；说明移动端其他平台未测边界 |

拟定入口合同：网页导出app:asgi_app，导入无副作用，启动在ASGI lifespan检查配置；包装Flet应用时透传lifespan和所有必要WebSocket/OAuth路径，禁止upload。worker为python worker.py；manage.py提供init/import/backup/restore，只有init建表，restore只写新目录且中断备份中未完成任务。Codex须按锁定Flet版本实现并验证，不把官方旧同步样例直接粘入1.0事件回调。示例服务启动可以使用：

```bash
/opt/a-stock-screen/current/.venv/bin/uvicorn app:asgi_app --host 127.0.0.1 --port 8550 --workers 1 --proxy-headers --forwarded-allow-ips 127.0.0.1 --no-access-log
/opt/a-stock-screen/current/.venv/bin/python worker.py
```

Caddy/Uvicorn默认access log应关闭或明确过滤OAuth查询串，应用与提供方异常链也脱敏；上述uvicorn关闭访问日志并不足以替代其余日志检查。仅信任127.0.0.1代理，demo使用--no-proxy-headers。FLET_WEB_NO_CDN=true等Web资源配置需实际生效。应用仍保留不含Token、授权码、私人笔记的短错误摘要。不要为了“方便排查”打印官方OAuth示例中的Access Token。

公网启用前实际检查：同标签页登录回跳、错误账号拒绝、/upload拒绝、跨站WS拒绝、私人路径不能访问、无刷新/锁屏重复任务。未提供配置时这些项保持未验证，不要求开发者索要secret来运行demo。

部署前所有者需实际提供：域名/DNS、OAuth app回调与secret、数字用户ID、VPS只读数据路径、worker的数据凭据。Codex只能生成占位配置，不能猜测或从聊天中拼出生产值。

## 4. 轻量停止规则

不以文件数、代码行数或单测数量验收；也不为了少一个文件把全部UI、认证和数据库堆进screen.py。需要的职责才分开，不做预留层。

S1能保存研究记录，S2能离开页面后完成更新，S3能接续未阅变化，即完成本轮。若Flet真实Web端或移动端浏览器上的登录、中文输入或重连严重不可用，保留已完成业务/存储，用具体失败证据提出一个局部决策；不能擅自并行建设Django、Streamlit、React或原生版本。
