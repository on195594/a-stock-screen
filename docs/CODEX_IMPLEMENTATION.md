## S1：一次扫描看得懂

**唯一目标：本人能独立扫描，理解为什么这几家公司进入研究范围、参照在哪里、资料有什么缺口，并加入观察。**

### 实施差量

1. **查询合同先于页面。** 复用现有快照与任务表，在 `get_peer_discover` 中分开返回最新尝试及状态、当前完整榜run、指定任务结果/诊断。完整榜选择规则不变；不能只过滤complete后隐藏新失败，不能把partial名次替换旧前三。无历史、零合格、无池外合格、损坏回退分别给出可显示原因。
2. **结果信息恢复到已有报告水平。** 复用 `screen.py:render_report/candidate_review_sections` 的数据组织，必要时只提取纯整理函数。主区展示前三＋参照、实际PB、三年逐年ROE及均值、各自日期/年度、个人状态；次区展开两项名次、计算方式、完整榜、行业/来源、枚举与排除原因。参照不合格仍展示原因，不在前三时单列；不重复计算算法。
3. **投资解释不新增评分。** 明确研究次序≠买入建议。对高ROE、低PB、年度波动、行业可比性给固定人工核查问题；区分已有事实与尚未核查项。不自动认定低估、风险已排除或业务可比，不扩展数据平台。
4. **首次与空状态可行动。** 空清单有“开始同业研究”；参照选择说明允许范围，不假装支持任意股票。不支持的对象、缺日历、缺配置均有原因和下一步；无完整榜不渲染沉默空白。首页尚无watch更新时显式说明并提供同业扫描入口，不仅依赖禁用tooltip。
5. **明确加入。** 从结果可幂等加入观察，已有记录只进入查看/编辑，不覆盖理由、不推进ack。详情仍保留既有保存能力；不得以未呈现的变化摘要诱导“已阅”。完整变化对照是S2任务，在接通前应说明能力边界并限制相应确认入口，不降低服务校验。
6. **任务与上下文。** 中文状态、真实阶段、不虚构逐证券进度；提供查看本次结果/诊断和适用的重试。历史任务按自身anchor/result_run_id打开，不能跳到当前选中的另一参照。新重试是显式新请求，范围/目标日重算变化须提示。公司返回恢复来源、参照、run和列表位置；首页进入则回首页，底部导航状态一致。浏览器返回/刷新不重提任务或写操作。
7. **只做必要的响应式整理。** 360/390/430宽度可阅读，不靠横向滚动宽表；主要实际数值清楚、辅助名次降级。不以换配色代替上述信息补齐，不新增状态框架。

### S1验证与退出条件

在现有临时库/合成fixture上补足：无历史、零候选、参照不合格、完整结果、partial有旧榜、partial无旧榜、无run失败、错参照历史任务、快照损坏。先测查询合同，再用动态Web实际点击验证：

- 不看README、不用CLI：空首页→选择参照→提交→对应结果→查看依据→加入观察→返回原比较。
- 前三与原算法一致；用户能从页面说明实际PB/ROE差异、采用年度、参照位置和未核查问题，不必逐个打开公司才获得基本比较。
- partial明确说明新缺口与旧榜日期；零结果有原因；重新打开历史任务不会改显示对象或自动再次提交。
- 保存仍持久、重复加入不覆盖、快捷加入ack为空；退出/过期后异步返回不重显私人资料。
- `make check`及扩展后的`make test-mobile`实际通过；理解性由本人操作反馈确认，不用自动化替本人宣称“看得懂”。无法本人验收则标pending。

**S1之后先交付评估，不自动进入S2，也不顺手改部署结构。**

## S2：加入以后能继续研究

**目标：数日后回来，知道上次研究到哪里、资料具体变了什么、下一步做什么。**

### 实施差量

1. **固定关注更新。** 实现 `request_watch_update` 与现有worker的watch分支，冻结研究中/观察的代码，默认排除paused；空清单拒绝，超过50家明确提示，不静默截断。不要求公司仍在原关注集合或同业前50，非正PB/ROE与已知ST仍能读取可得事实；不写新同业名次。
2. **沿用任务可靠性边界。** request_id/别名先于重新读取清单和日历；同ID不同intent拒绝；active范围去重、队列上限、单worker锁、网络在事务外、有限终止、固定路径及恢复验证继续覆盖。watch新增逻辑必须有自己的失败与恢复分支测试，不能仅引用peer已通过。
3. **显式已阅对照。** 服务复用事实比较逻辑，返回已阅→当前的PB及日期、年报年度/公告/版本/逐年ROE变化。无ack是首次待阅，缺失/规则/范围变动单列；仅checked_at变化不制造财务变化。先实际展示可用事实，再显式ack；缺口不拼接成新完整资料，ack不倒退、保存备注不推进。
4. **首页成为研究入口。** 数据异常、需要复看、研究中、观察分层；显示上次理由和next_check。暂停默认不在提醒/待阅数里，可展开恢复。重要事实变化与仅数据日更新区分层级，不把日历推进当作公司风险变化。历史任务在次级区域。
5. **详情支持继续判断。** 显示最近peer名次及其旧参照/日期，不把watch更新说成重新排名；事实、个人判断与数据状态分开。经校验后可打开外部笔记，来源信息可展开。复用reason/next_check/note_url，不增加自动投资结论字段。
6. **输入与故障边界。** 中文编辑不被轮询重建；返回提示未保存，断线禁写，重连核验身份和revision；响应不明确时先查询确认，不重放写操作。设置优先展示资料可用性、最近更新和阻断原因，而非绝对路径/内部ID。

### S2验证与退出条件

- 合成关注公司退出前50、非正PB/ROE、部分失败、暂停恢复、连续多次未阅、同值重查均有覆盖。
- 本人完成“重新打开→看到上次下一步→更新固定关注→看旧值与新值→保存新判断→明确已阅”；保存、刷新、应用重开后数据一致。
- 单独watch更新后旧peer名次不变；暂停不产生默认提醒；失败与旧可用事实日期分开。
- 双击/两标签页/跨日重试、请求后清单改变、worker强制中断和发布窗口恢复通过相应服务/进程检查。
- 继续运行全部`make check`及`make test-mobile`；报告本人理解性与真实移动端仍待测的范围。

## S3：真机与生产使用验收

**目标：完成已实现用户任务的实证验收，不再以容器运行或测试数量作为交付。**

### 验证与必要补差

1. **本人认证。** 同标签页GitHub OAuth、正确数字ID、错误ID、过期、退出、深链接和WS重连；匿名200不代表登录成功。缺本人操作则pending，不代登录或索取聊天中的secret。
2. **有限真实数据。** 仅在明确授权、Token本机配置后，选一个适用参照做有限扫描，再更新少量观察公司。核对目标日、公司身份、实际数值/年报年份/来源、结果日期及范围；不以fixture冒充生产，不反复联网凑成功。
3. **真机研究任务。** 所有者常用手机实操登录、扫描、读比较、加入、中文输入保存、返回、锁屏/网络切换、回来查任务、看变化与已阅。360/390/430浏览器自动化是补充，不能代替真机；其他平台未测如实记录。
4. **可测性能。** 分别记录冷启动到可操作、热切页、任务受理反馈、保存反馈；记录设备/浏览器、网络、缓存和资源加载条件。区分服务端查询、Flet启动、字体/CDN、数据更新耗时。先取得基线，再由所有者确认可接受目标，不凭感觉宣称优化。
5. **私人数据恢复。** 补齐必要的显式backup/restore维护入口并验证：SQLite备份后从备份库复制引用快照；恢复到新目录、禁网、mode/schema一致，queued/running标interrupted，不自动执行旧任务。运行数据不清理，正式替换另获授权。
6. **沿用部署。** 只维护Compose/Nginx/现有deploy脚本，核查角色凭据、Host/Origin、WS、上传关闭、日志无secret、工作区非静态资源。生产更新/重建/重载须另获授权，不创建Caddy/systemd并行资产。
